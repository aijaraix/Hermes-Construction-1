# Stop and escalation rules

Continue normal bounded implementation, repair and verification autonomously under the approved campaign. Do not ask again for unchanged valid authority.

Stop for a genuine hard gate: denial/revocation/actual grant expiry; project/role/branch or material scope change; required new regression that cannot safely be repaired within the current milestone; inability to preserve/recover a meaningful stage safely.

Database unavailable: NOT RUN — DATABASE UNAVAILABLE. Provider unavailable: live-provider gate NOT RUN. Faithful browser unavailable: physical gate BLOCKED / UNVERIFIED. These labels permit only the conditional engineering continuation explicitly requested by the Owner, never false physical acceptance. An actual parser/required engineering failure is not an infrastructure skip.

The campaign does not authorize merge to main, production deployment/cutover, destructive database/production changes, money/spend or live-money actions, changed credentials/security authority, cross-project source changes, force push or weaker tests. Do not manufacture professional, AHJ, legal or physical verification from internal/simulated evidence. Stop before a step requiring any of those actions.

Do not restart/re-certify the Gateway bridge, create Workers to avoid product work, create new VPS infrastructure, invent historical commit objects or reset legitimate work. Preserve exact pre-test runtime bytes. Do not use production database/provider credentials merely because they exist in an environment.
