# AEDRYX Final External Visual Acceptance

## Why this exists

The Astra Worker browser has demonstrated environments where WebGL is disabled and Three.js cannot create a context.

That environment must not be used to falsely fail application code or falsely pass visual QA.

A separate external browser has successfully rendered the current public AEDRYX WebGL scene.

## Acceptance procedure

After the full combined campaign is durably preserved:

1. obtain separate Owner authorization for the acceptance deployment;
2. deploy the exact final Accepted Head to the existing AEDRYX Railway service;
3. verify terminal deployment success and exact source relationship;
4. open the live AEDRYX URL in a WebGL-capable external browser;
5. capture and inspect the required desktop/mobile scenes.

## Required 3D checks

Use timeline/view modes to inspect:
- empty site;
- site prep/layout;
- excavation;
- foundation;
- framing;
- roof framing;
- dry-in;
- rough MEP;
- x-ray/systems;
- construction-complete house.

Confirm:
- no giant opaque roof proxy;
- house silhouette is recognizable;
- walls/openings/roof/foundation/framing are meaningful;
- terrain/excavation visibly change;
- people/equipment/materials are believable in scale;
- systems are understandable;
- current/next/blocked/changed status is coherent with scene.

## Required shell/security checks

- login/session;
- profile/account menu;
- Sign out;
- refresh/back after logout;
- desktop/mobile navigation;
- landing page;
- CTA routing.

## Marketing checks

- OpenArt assets render crisply;
- no asset is presented as an actual product screenshot;
- copy does not overstate current physical robotics/autonomy;
- AEDRYX brand name/title/metadata are correct.

## Result

Return:
- PASS/FAIL by packet/stage;
- screenshots;
- exact deployed Accepted Head;
- remaining defects;
- remediation recommendation if needed.
