# AEDRYX Visual Completion Master

## Mission

Transform AEDRYX from a technically functional but visually abstract construction platform into a professional, spatially truthful construction twin.

The initial reference project is **Academy House 001**.

The visual twin is not decorative. It is a human-readable projection of the same canonical physical state used by planning, logistics, construction methods, inspection, and eventually robotic execution.

## Product acceptance principle

Every visible physical object must satisfy:

1. **Identity** — it looks recognizably like what it is.
2. **Scale** — it is rendered at the same real-world dimensions used by the physical model.
3. **Placement** — its position and orientation come from canonical world state.
4. **State** — its visual form reflects construction state.
5. **Behavior** — it occupies space consistently with its physical meaning.
6. **Truth** — simulated, estimated, imported, verified, and approved states are not conflated.

## Immediate priorities

### Priority 1 — House recognition
A normal observer must immediately recognize a house under construction rather than a collection of generic boxes.

### Priority 2 — Site recognition
The building must visibly exist on a parcel with ground, grade, access, staging, and mutable excavation state.

### Priority 3 — Construction progression
The scene must visibly change as work progresses.

### Priority 4 — Scale confidence
People, equipment, openings, materials, walls, roofs, rooms, and site features must remain proportionally correct.

### Priority 5 — Work visibility
The user must be able to answer “what is happening right now?” from the interface itself.

## Reference construction sequence

The reference experience must support at least:

0. Existing/empty site
1. Site preparation and survey
2. Excavation
3. Foundation
4. Framing
5. Dry-in
6. Rough MEP
7. Close-in
8. Exterior/interior construction finishes
9. Construction-complete house

## Visual modes

At minimum:
- Finished / normal view
- Architectural shell
- Structural/framing
- Construction state
- MEP/systems
- X-ray/section
- What Changed
- Timeline/replay

## Relationship to deeper world-model work

This campaign is deliberately pragmatic.

Do not pause visible progress to build a universal CAD or physics engine.

When existing primitives cannot accurately represent a required visual condition, add the **smallest canonical physical primitive** required to represent it correctly.

Examples:
- sloped plane for a pitched roof;
- hosted opening for a door/window;
- arbitrary wall path/profile for non-orthogonal geometry;
- terrain subtraction for excavation;
- exact actor bounds for scale and clearance.

The geometry/world model should grow from real product requirements, not speculative abstraction.

## Completion definition

Visual completion does not mean photorealism.

It means:
- professional;
- legible;
- dimensionally coherent;
- constructionally believable;
- state-correct;
- useful to a builder;
- replayable;
- inspectable;
- honest about uncertainty.
