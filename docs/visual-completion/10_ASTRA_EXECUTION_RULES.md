# Astra Execution Rules — AEDRYX Visual Completion

## Role

Astra is an implementation Worker for this program.

Astra does not own the roadmap.

## Required behavior

1. Recover the exact governed source and verify branch/base before editing.
2. Read the complete controlling visual-completion package.
3. Execute packets in prescribed order.
4. Keep scope bounded to current packet.
5. Test before checkpoint.
6. Perform actual rendered visual inspection where the environment permits it.
7. Commit and preserve each completed packet before starting the next.
8. Reconcile source SHA, tests, visual evidence, and known limitations at every checkpoint.
9. If the session degrades or context is nearing limits, stop at the latest preserved checkpoint and produce a continuation handoff.
10. Continue from preserved state; never redo completed packets merely because a Worker changed.

## Anti-tangent rules

Do not:
- redesign the roadmap;
- create a new product architecture;
- introduce unrelated frameworks;
- rewrite healthy subsystems for elegance;
- create speculative abstractions “for the future”;
- expand into generalized robotics;
- rebuild the Control Plane;
- redesign AI routing;
- perform unrelated dashboard polish;
- declare visual acceptance based only on automated tests.

When an unrelated defect is found:
- record it in a deferred ledger;
- continue unless it directly blocks current visual acceptance.

## Minimal-primitive rule

If current geometry cannot represent a required physical form correctly, add the smallest reusable canonical primitive necessary to satisfy the current acceptance case.

Do not build a universal CAD engine in advance.

## Preservation cadence

Maximum unpreserved work:
- one coherent packet;
- preferably smaller checkpoints within large packets.

Required sequence:
`implement → test → visually inspect → commit → preserve → verify exact source → continue`

## Deployment

No production deployment is authorized by this document.

Deployment remains a separate Owner action.

## Honesty rules

Never claim:
- browser acceptance without actual browser/render evidence;
- physical truth from simulated fixtures;
- professional approval from internal checks;
- successful visual fidelity merely because a Three.js mesh exists;
- real sourcing/pricing from hard-coded sample suppliers.

Report PASS, FAIL, and BLOCKED accurately.
